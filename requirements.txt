# --- Data handling ---
# Capped below 3 because that is what actually runs: mlflow 3 requires
# pandas<3, so `pip install -r` on a pandas 3.x environment silently
# downgrades it. Stating >=2.2 while the resolver installs 2.3.3 would make
# the file a description of an environment nobody has.
#
# The code supports both lines regardless -- the categorical selector in
# build_features keys off `not is_numeric_dtype` rather than
# is_object_dtype, because strings arrive as `object` under pandas 2 and as
# `str` under pandas 3. Verified against both, and the parquet schema is
# explicit (float32/int64/string), so the feature matrix is identical either
# way. Lift the cap when mlflow supports pandas 3.
pandas>=2.2,<3
numpy>=1.26
pyarrow>=15.0

# --- Experiment tracking and data versioning ---
# The SQLite tracking store needs no server. It is required rather than
# preferred: MLflow 3 refuses the legacy mlruns/ file store by default, and
# the Model Registry has never worked against it.

dvc>=3.0
